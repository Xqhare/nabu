## Musings

### Secure Container

A new single value parent (wrapper essentially), that stores the same values 3 times. Only if 2 of the values are the same, is the value considered secure and thus read and returned. Saturn V style.

Should 3 of 3 agree = Read and return value.
2 of 3 agree = Read and return value. Add possibility to warn the user about degradation for any implementation.
None agree = Error out.

To check, the value does not need to be deserialised, a simple byte match should suffice. (See deterministic byte structure => Consider banning OBJ use and only permit OOBJ here => Would be the only place in the spec where only one value isnt allowed, bad decision)

Very `Array` like, but without the need for an element count.

### Deterministic Byte Structure

Xff is already deterministic, with the important exception of the general Object type.

Really this only needs to be added to the spec as an Info block or similar.
