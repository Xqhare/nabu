# `.xff` specification v3

> [!note]
> ***This version is not yet finalized.***

Started musing during finalisation of version 2 on 2025-03-17;

## Musings about a future version 3

### Error correction
V2 added error detection, this would be the next logical step.

### Add version to Values
Add a version byte to each value except for `Null` and `Boolean`.

Value versions:
- Version 0: Most values did not yet exist - Also, the still existing Values have changed enormously -> Skip v0?
- Version 1: The same as in the v1 spec. (No checksum, only `EV` marker)
- Version 2: The same as in the v2 spec. (Checksum and `EV` marker)

#### `Number`
Add `Number` version 3 that accepts `Float` and `Integer` to encode them in binary directly?
Add `NaN` and `Infinity` as xff byte values? 14 & 15 would fit nicely. What about `NegInfinity`?

- V1: v1 spec, no checksum
- V2: v2 spec, checksum

For binary representation it seems to be easiest to split `Number` into `Integer`, `Signed` and `Float`.

`Integer` could be stored LEB128 encoded.
`Signed` could be stored LEB128 encoded with the second most significant bit of the first byte reserved for a sign bit.
`Float` would need to be IEEE-754 and could now also store `NaN` and `Infinity`.

As the binary representation would expand the version count to 5, adding one more version to encode `Nan`, `NegInfinity` and `Infinity` seems like a good idea.
Also, the idea of using a sub version scheme for `Number` is a good one.

| Version | Description |
| -------------- | --------------- |
| 1 | v1 spec, no checksum, EV marker |
| 2 | v2 spec, checksum, EV marker |
| 3 | v3 spec, sub version, checksum, EV marker |

| Sub version | Description |
| -------------- | --------------- |
| 0 | `Nan`, `NegInfinity`, `Infinity` |
| 1 | `Integer` |
| 2 | `Signed` |
| 3 | `Float` |

##### `NaN` and the `Infinity`s
Storing `NaN` and `Infinity` as they are in floating point representation seems like a storage space waste.
In a `f32` they still take up 4 bytes. I can reduce this.

`Nan` would take 1 byte, the `NaN` marker.

`Infinity` would take 1 byte, the `Infinity` marker. \
`NegInfinity` would take 2 bytes, the `-` minus sign and the `Infinity` marker.

This way I save space and can add a bit more flair.

#### `Text`
Add `Text` version 3 that accepts `UTF-8` and / or `UTF-16`?

#### Data stores
Any data store should be able to host any version of any value as long as the version of the value is not larger than the version of the data store it is contained in.
